# UNITY RUST — сайт і панель

Node.js-сервер для сайту UNITY RUST: статика, тикети, кабінети, промокоди,
бани, Discord-сповіщення та RCON-команди.

## Локальний запуск

Потрібен **Node.js 24** (через `node:sqlite`).

```powershell
cd САЙТ
npm install
Copy-Item .env.example .env
# заповни .env своїми значеннями
node --env-file=.env server.js
```

Сайт: <http://127.0.0.1:8088/>

`nexus-site.config.json` більше **не читається**. Усі налаштування — тільки
через змінні оточення.

## Деплой на Render

1. Запуш репозиторій у GitHub.
2. Render → **New → Web Service**.
3. Якщо це монорепозиторій, вкажи **Root Directory**: `САЙТ`.
4. Налаштування сервісу:

| Параметр | Значення |
|---|---|
| Runtime | Node |
| Build Command | `npm install --omit=dev` |
| Start Command | `node server.js` |
| Health Check Path | `/healthz` |
| Node Version | `24` |

5. Додай змінні в **Environment**. Секрети не зберігай у `render.yaml`.

### Обов'язкові змінні

| Змінна | Приклад | Навіщо |
|---|---|---|
| `NODE_ENV` | `production` | вмикає production-перевірки |
| `PUBLIC_BASE_URL` | `https://unity-rust.onrender.com` | Steam-редіректи, cookies |
| `ADMIN_PASSWORD` | довгий випадковий пароль | вхід в адмінку; мінімум 12 символів |
| `OWNER_STEAM_ID` | `7656119xxxxxxxxxx` | SteamID64 власника (17 цифр, починається з `7656`) |
| `RCON_URL` | `wss://rcon.example.com:28016/secret` | керування Rust-сервером |

### Бажано

| Змінна | Приклад | Навіщо |
|---|---|---|
| `DATA_DIR` | `/var/data` | SQLite, тикети, бани, промокоди |
| `PLAYERS_FILE` | `/var/data/players.json` | статистика гравців для лідерборду |
| `RCON_NAME` | `UNITY ADMIN` | підпис у RCON |
| `SITE_MODE` | `public` | сайт без БД і RCON (безкоштовний хостинг) |
| `DISCORD_BOT_TOKEN` | токен бота | усі сповіщення йдуть через бота |
| `DISCORD_GUILD_ID` | ID сервера | Discord-сповіщення |
| `DISCORD_TICKETS_CHANNEL_ID` | ID каналу `#admin-tickets` | куди бот пише (єдиний канал для тікетів/скарг) |
| `DISCORD_TICKETS_CHANNEL_NAME` | `admin-tickets` | якщо ID не заданий — пошук каналу за назвою |
| `DISCORD_WEBHOOK_URL` | `https://discord.com/api/webhooks/...` | запасний варіант, якщо бот не заданий |
| `DISCORD_ROLE_IDS` | `{"admin":"123","moderator":"456"}` | ролі Discord |
| `DAILY_REPORT_HOUR` | `18` | година щоденного звіту (UTC) |

### Важливо про Render

* **RCON на `127.0.0.1` з Render не працює.** Render — це інший контейнер.
  Потрібен публічний `wss://` (тунель, VPN або публічний IP із захистом).
* **Безкоштовний план не має постійного диска.** SQLite і заявки зникають
  після рестарту/деплою. Для збереження даних потрібен платний план і disk,
  змонтований у `/var/data`, тоді `DATA_DIR=/var/data`.
* `PLAYERS_FILE` має вказувати на файл, який реально існує в контейнері.
  Просто Windows-шлях `D:\RustServer\...` на Render не працює.
* Якщо `PLAYERS_FILE` немає, лідерборд просто буде порожнім — сервер не впаде.

### Режим без бази (безкоштовний хостинг)

Найпростіше — один перемикач:

```text
SITE_MODE=public
```

Він вимикає і БД (SQLite в RAM), і RCON. Окремо можна поставити лише
`DB_MODE=memory`, якщо RCON потрібен.

У публічному режимі сайт навмисно мінімальний і безпечний:

* **Працює:** головна, правила, новини, статистика онлайн, лідерборд,
  **скарги** (з файлом доказу або без) із відправкою в Discord.
* **В розробці:** магазин, заявки в стаф, вхід через Steam, кабінет,
  історія покупок, «Мої прив'язки».
* Онлайн і кількість гравців беруться **без RCON** — UDP-запитом A2S до
  query-порту Rust (`SERVER_QUERY_HOST`, `SERVER_QUERY_PORT`, типово
  `28017`). Якщо сервер вимкнений — сайт показує «невідомо», а не падає.
  Якщо Rust за playit.gg-тунелем, зроби окремий **UDP-тунель на 28017**
  і встав його адресу в ці змінні.
* Після кожного рестарту/деплою історія скарг очищається.
* Щоб скарги не губились, задай `DISCORD_BOT_TOKEN` + `DISCORD_GUILD_ID` —
  кожна нова **скарга** дублюється в Discord через бота в канал
  **#admin-tickets** (`DISCORD_TICKETS_CHANNEL_ID` / `DISCORD_TICKETS_CHANNEL_NAME`).

### RCON, якщо сайт на хостингу, а Rust — вдома

`RCON_URL=ws://127.0.0.1:28016/...` працює **тільки коли сайт запущений
на тій самій машині**, що й Rust-сервер.

Якщо сайт на Render/іншому хостингу, потрібен публічний `wss://`:

1. **Cloudflare Tunnel** (безкоштовно): тунель на `http://127.0.0.1:28016`,
   публічний hostname → `wss://rcon.твій-домен/<пароль>`.
2. Або ngrok / playit.gg з TCP-тунелем на порт `28016`.
3. Або відкрити порт `28016` на роутері — **небезпечно**: RCON захищений
   лише паролем, тому пароль має бути довгим і випадковим.

Важливо: тунель працює, лише поки твій ПК і Rust-сервер увімкнені. Якщо
ПК вимкнений — сайт відкривається, але статистика/кік/бан через RCON
будуть недоступні.

## Безпека

* Секрети більше не читаються з `nexus-site.config.json`; тільки `process.env`.
* Права власника перевіряються за **серверною Steam-сесією**, а не за
  `steamId`, який прислав клієнт. Підставити публічний SteamID власника
  й отримати адмінку більше не можна.
* Пароль адмінки порівнюється за сталий час.
* Cookie сесії: `HttpOnly`, `SameSite=Lax`, `Secure` у production.
* Статика віддається за білим списком: `index.html`, `i18n-phrases.js`,
  `images/*`, `videos/*`. `server.js`, `package.json`, `data/*.db` і
  `nexus-site.config.json` недоступні по прямих посиланнях.
* У production сервер не стартує без `ADMIN_PASSWORD`, `OWNER_STEAM_ID`,
  `PUBLIC_BASE_URL` і `RCON_URL`.

## Що зробити зі старим `nexus-site.config.json`

1. Перенеси значення з нього в Render → Environment.
2. Переконайся, що файл є в `.gitignore`.
3. Після перенесення файл можна видалити локально — сервер його не потребує.
